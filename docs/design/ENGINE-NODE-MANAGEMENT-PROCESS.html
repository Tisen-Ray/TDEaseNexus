TDEASENEXUS · BACKEND ENGINE · NODE LIFECYCLE

数据处理工具（节点）管理

产品只读种子 → 用户可写 catalog → 客户端记录 digest → 后端按 id 绑定物化 → 引擎经 config["nodes"] 绝对路径注入执行。中间任何一步改字节，都是一次新 revision。

管理面在哪里

一个目录就是全部接口

  • TDEaseNexus-Data/backend/nodes/<id>/rules.smk 存在即节点；目录名 = id，内容 sha256 = digest。
  • _ 前缀是草稿/模板（如 _template），扫描器跳过，不会进 catalog。
  • AI 与用户都能直接改：新增包、改 flags、把 <block>.bin_dir 指向宿主安装目录。

稳定性的代价

冻结 vs 活链接

  • digest 在 prepare 时冻结进 Run 记录：改节点 = 新 revision，正在跑的 Run 不会换定义（结果归属于产出它的 revision）。
  • 没有按 digest 的 immutable snapshot：Run 按 id 绑定节点，执行用 catalog 当前字节；digest 是 provenance，从不构成执行隔离（node_catalog.py）。
  • AI 若“改 Run 里的节点”，改的其实是全局 catalog；后续执行立即用上新字节 —— 旧字节不会、也无法被隔离保留。
