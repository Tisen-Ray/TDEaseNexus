TDEASENEXUS · BACKEND ENGINE · SEQUENCE

前端提交 → 后端引擎执行

一次 Run 从 Studio 的冻结计划到 Snakemake 落盘执行：提交的是不可变 commit，节点二进制经 config["nodes"] 绝对路径注入，Run 目录不持有节点内容。

提交的到底是什么

不可变 commit

  • 冻结的是 workspace_files 映射 + Snakefile 全文 + config + nodes(id+digest)，不是路径引用。
  • 节点身份 = 目录内容 sha256；Snakefile 或节点任何字节变化都算新 revision。
  • 提交后 run.json 永不重写，状态全部由 events.jsonl 派生。

执行侧的三条硬约束

一次只跑一个 Run

  • execution.claim 全局唯一执行槽：dry-run 与真 Run 共享，API 与 worker 互斥。
  • 节点二进制经单一接缝 config["nodes"] 以 catalog 绝对路径注入；Run 目录内不写任何节点内容（bindings.py）。
  • 引擎子进程剥离全部 TDEASE_*，没有环境变量后门。

已知薄弱点

监督缺口

  • worker 处于监督之下：反复崩溃报 worker_unstable；父进程消失时 worker 自行退出（孤儿 poller），避免 API ready 而 Run 永久 QUEUED。
  • 执行槽身份是 <pid>:<create_time>，不是裸 pid —— Windows 激进复用 pid 也不会让队列卡死。
