TDEASENEXUS · BACKEND ENGINE · WORKER PROCESSES

工作流进程与监督

serve 拉起 worker，worker 轮询队列、抢全局执行槽、执行一个 Run；引擎与工具是它的后代进程。空转或跑完都回到 1 秒轮询。

进程拓扑

一条链，全是子进程

  • Electron main → backend serve → worker → engine_runner/snakemake → 工具子进程。
  • 客户端停止时用 taskkill /T /F 连根拔；硬杀客户端则 backend/worker 变孤儿。
  • 引擎子进程剥离全部 TDEASE_*，节点只能经 config["nodes"] 绝对路径注入访问。

生命周期护栏

三层认领 + 孤儿回收

  • execution.claim：全局唯一执行槽（API 的 dry-run 与 worker 的 Run 互斥）。
  • run claim：O_CREAT|O_EXCL，防止同一个 Run 被执行两次。
  • engine pid record：崩溃后由启动时的 reconcile_orphaned_runs 收尾并写终态事件。

已知缺口

两处静默失败

  • worker 受监督：反复崩溃报 worker_unstable；父进程消失时 worker 检测到 --parent-pid 死亡自行退出（孤儿 poller 护栏），不会出现 API 仍 ready 而 Run 永久 QUEUED。
  • 执行槽身份是 <pid>:<create_time>（storage.py process_identity）：Windows 激进复用 pid 也不会让队列永久卡住。
